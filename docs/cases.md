# SDK 共同验收

## SDK 用户故事

用户故事 `SDK-US-NNN` 表达完整使用目标。`SDK-CASE-NNN` 是可独立录制和回放的一条流程，
其归属、输入、步骤与预期由场景定义。同一流程可以有多条断言。查找 case 时使用场景中的
`storyId` 和 `id`。[场景目录](../data/scenarios) · [共享词汇表](../GLOSSARY.md)

只有指定 agent type 和证据层的全部必需 case 通过，才可声明故事通过。

### 共同边界

真实录制、官方 SDK 验证和消费者仿真分别报告。合成进程、协议容错和精确竞态由代码测试覆盖。
审批拒绝和主动中断是实际用户操作。工具、审批、问答或子 Agent 未触发时，报告未触发，
保留原始行为及输出。

## 验证 case

以场景的 `required` 为默认值。有 agent binding 明确赋值时，采用该 agent type 的值。
必需 case 缺少通过证据时，门禁保持未通过。可选 case 仍须报告实际结果，并校验已有材料的
来源及完整性。Codex 延迟审批路径的当前例外及原因由其 binding 记录。
[Codex binding](../data/scenarios/bindings/codex.json) · [Claude binding](../data/scenarios/bindings/claude.json)

## 流程语义

### 证据与通过条件

分别取证提交、原生接受、实际执行和业务目标。通过严格回放只证明协议与材料匹配。
只有目标允许拒绝时，观察到拒绝才可通过该目标。录制冻结原生版本、配置和观察结果，
回放的断言以实录证据为限。验收标准收紧后，保留原录制和报告，单独记录复核结论。

配置证据区分请求值、确认回执、原生观察值与生效范围。只有确认回执时可报告已接受；
要求实际生效的目标缺少原生观察证据时记为 `unverified`。任务文本、耗时、token 数量和模型自述
都不能作为配置观察证据。

### 输入、工具、审批与问答

- 连续输入（001）要在第一次结果后继续从同一会话获得第二次输入对应的事件与结果。两次输入间
  可以没有新事件，`idle` 与结果的顺序取原生观察值。执行期追加（005）在观察到实际进度后提交。
  接受时关联后续处理，拒绝时保留原生错误与原执行终态；调度、抢占、排队及重发均以实际行为为准。
- 结构化输入（002–004）的答案必须依赖读取所发的原生非文本内容。混合输入要核对声明的各内容部分。
  仅传输成功、正常终态或从提示词猜中都不足以通过。使用原生内容类型完成验证。
- 工具执行（006–007）和任务结果分别验收。应用工具要用实际原生请求的有效句柄答复，之后观察任务继续并完成。
- 审批（008–012）用原始有效句柄执行用户决定，再检查后续行为与终态。拒绝后任务可以失败。
  自动批准、模型放弃和协议 `Reject` 不计入用户决策。延迟审批要求先在未答期间取得独立原生事件和关联控制回执，
  再回答审批并观察终态。
- 问答（013–015）通过原生请求的题目标识完整回答，再观察任务继续及结果。多题要求出自同一原生请求。

### 子 Agent 与详细交付

- 直接、嵌套、并行和后台行为（016–019）须绑定原生子身份与真实父子关系。嵌套需证明根到子、
  子到孙两条父边。并行需证明至少两个子 Agent 的活动实际重叠，并独立归属输出和完成结果。
  后台行为需在根执行结果之后观察已确认的子 Agent，并取得该子 Agent 的最终结果。
- 详细交付（020）在打开 Session 前选定策略，用同一材料比较 `preserve` 和 `suppress`。子归属确认后，
  `suppress` 至少省略一条允许过滤的纯详情，其余交付保持原序和内容。身份、关系、生命周期、终态、
  父工具结果、工具请求、审批与问答权限，以及带未知字段或混合内容的事件均受保护。历史和原始录制独立于交付策略。

### 模型与思考配置

- 选择或切换模型（021–024）必须有明确请求和原生证据。切换用不同模型值，按首次输入前或两次执行间
  的顺序区分生效范围。首次输入前的切换（022）需记录确认与提交顺序，并通过原生观察值证明新模型生效。
  执行中请求遇到拒绝时保留原因和当前执行终态，接受时记录实际观察的范围。
- 模式、预算、effort 和展示（025–028）各自取证。Codex 只观察到 `model_reasoning_effort` 时，独立模式保持未通过。
  已废弃的预算设置不证明硬上限。`effort` 先验证创建时的值，再在首次结果后请求不同的值并提交第二次输入。
  Claude 更新前的 `get_settings` 是预检，`apply_flag_settings` 的回执只表示接受。更新后缺少新的原生观察值时，
  生效仍为 `unverified`。
  展示验收要求字段和值正确透传、匹配原生回执并完成后续执行，视觉效果只作补充观察。
  [Claude 配置适配](../drivers/claude/official/claude_driver/adapter.py)
- 子配置（029）目前只比较模型。原生事实可以证明继承、默认或覆盖；未暴露子模型时保持未知。

### 中断、关闭与独立查询

- 中断（030）要求实际执行进度、原生确认和执行终态。保留先完成后中断的竞争结果，不计入成功中断。
- 本地关闭（031）验收自有进程回收、交互结束和后续交互拒绝。远端断连（032）需要用独立连接或健康检查证明
  同一服务仍可用。公开 WSS 部署单独取证。
- 独立查询（033–036）显式指定存储范围。发现、读取元数据和读取完整主内容分别取证。子历史需保留保存的子身份、
  原生顺序和父子关联，主历史中的摘要不够。已有子 Agent 的发现用同一 execution 的独立连接，正式观察入口零输入，
  通过发现接口取得已有身份和关系。原生分页或切片至少读取两个窗口，核对顺序、边界和可判定的终点。
  [既有子 Agent 的录制与回放](design.md#材料计划与运行配置)

### 上下文注入

- 上下文注入（037–038）由后续查询核对只通过注入发送的随机事实。空闲注入后经过无模型调用的控制屏障再查询；
  原始帧须证明注入没有启动额外执行或 assistant 输出。执行中注入需要在原生执行进度后发出，记录原生接受或
  拒绝，并区分当前执行是否消费与后续查询能否读取。
  [Codex 注入实现](../drivers/codex/official/codex_driver/injection.py) · [Claude 注入实现](../drivers/claude/official/claude_driver/injection.py)

## 待实现与不支持

`planned` 表示尚无完整录制路径，`unsupported` 表示已知原生能力不支持。驱动无法执行现有原生能力时
报告 `blocked`。分别报告未触发、失败和缺证据；这些状态都保留原有门禁要求。

## 用户故事的原生适配说明

Session 的输入语义、回答权限、历史查询与子详情过滤由对应 SDK 合同定义。场景和 binding 声明录制路径及限制，
录制驱动提供该路径使用的原生请求和实际检查。[Codex 驱动](../drivers/codex/official/codex_driver) · [Claude 驱动](../drivers/claude/official/claude_driver)
